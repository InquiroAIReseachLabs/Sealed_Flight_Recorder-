Sealed Flight Record engine test harness

v1.0 evaluation release. A plain page over the engine bundle (engine/sfr.js) for the browser tests in CI: seal a PX4 flight log, verify a record, run the tamper demo.

Files you choose are read in this tab and never uploaded. The page fetches only its own files from this site: the engine when it loads, and the sample log when the tamper demo starts.

Seal a flight log

The engine is the sfr command line built for the browser. It reads the log, runs the rules, and writes the record (.sfr) and its report (.sfr.md), exactly as sfr seal does.

Up to 100 MiB in the browser; the command line has no limit.

Rules

A QGroundControl parameter export with a # Firmware: <version> line. Without one, R2 and R3 fail, because there is nothing to compare the log with.

Same bytes as the command line (optional)

With the same log, rules, baseline, key and seal time, sfr seal --key sfr.key --evaluation-only --seal-time <time> writes a record and report identical to the ones made here.

Without one, the page signs with its in-browser evaluation key (below).

Verify a record

    
Checks the record's Merkle root and Ed25519 signature against a public key, as sfr verify does. With the flight log as well, it re-reads the log, replays the embedded rules and baseline, and requires identical results, configuration and events.

Tamper demo

    
Runs the steps of scripts/run_demo.sh on the bundled sample log, a multicopter flight from PX4 v1.17.0 simulation (mc_flight_1.ulg), fetched compressed from this site when the demo starts: seal it, verify it, change a COMMAND event in a copy of the record, change a parameter in a copy of the log. Each step shows the command it stands for, what the engine printed, and whether that is the expected result.
